## Deliberate decisions / deviations

- **Single `POST /api/sos` path, content-type negotiated** — multipart and JSON
  share one route (FastAPI can't cleanly do two same-path handlers); matches
  the contract's "JSON variant" section.
- **`ai_client.py` seam**: tries `packages/ai-engine/pipeline.py` +
  `assess_and_route` only when `SAHAYTA_LLM_BASE_URL`/`MODEL` are set; otherwise
  the rule fallback — a behavioral twin of `frontend/lib/demo-assess.ts` (same
  regexes/scoring; the demo fixture scores exactly 4 on both). `model` is always
  honest (`rule-fallback-v1` vs the engine's label). Agent 6 drops in the real
  engine without touching the backend.
- **Alert rendering**: template fill (`data/alert-templates/`) + admin body
  appended, ≤480 chars; `custom` type renders title+body. AI-engine rendering
  plugs in when Agent 6 lands.
- **Risk**: `services/risk.py` documents the v1 formula; seed honors
  `seed_hints` (Patna 82/high) with contributions normalized to sum to the hint —
  logged, never hidden. Forecast is a deterministic 72h projection (no network).
- **Media hashing**: 64-bit dHash via Pillow when decodable, else `sha256:<hex>`
  (prefix marks exact-match-only semantics). Duplicate-photo re-upload creates a
  `possible_duplicate` safety flag + `needs_review` — never silently dropped.
- **Test isolation**: per-test private DB file copied from a seeded template
  (the savepoint-join approach doesn't survive `session.commit()` on this
  stack — verified empirically, so I switched to the bulletproof option).
- **Single-file `models.py`/`schemas.py`** instead of per-model modules — the
  data-models doc describes schemas, not file layout; one file each is easier
  to keep in sync at this stage.
- **Rate limits**: in-memory sliding window per key (per-process; fine for the
  v1 monolith, documented).
- `GET /api/admin/audit` and `GET /api/admin/safety/flags` return bare arrays
  (the frontend's typed client expects arrays, matching the contract examples).

## For Agent 6 (AI engine)

- Seam contract: `packages/ai-engine/pipeline.py` must expose
  `assess_and_route(description, language, lat, lon, photo_description,
  photo_path) -> dict|object` with keys `severity, rationale, rationale_en,
  area_tags, category, priority, suggested_skills, model` (+ optional
  `prompt_tokens, completion_tokens, latency_ms`). It is called **only** when
  `SAHAYTA_LLM_BASE_URL` and `SAHAYTA_LLM_MODEL` are set; any exception falls
  back to rules (intake never fails).
- `packages/ai-engine/alerts.py` may expose `render_multilingual(alert_type,
  languages, district_names, body, title, extra)` — used when an LLM is
  configured; templates remain ground truth otherwise.
- The rule fallback is the behavioral bar: your engine must also score the
  demo fixture at severity 4 (`tests/test_sos.py::test_assess_endpoint_demo_fixture_scores_4`
  guards this — it will exercise your path once `SAHAYTA_LLM_*` is set).
- If you need contract changes, the doc is FROZEN: file a `MIGRATION.md` note
  per §12 and bump the version.
